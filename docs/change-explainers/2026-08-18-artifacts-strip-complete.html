交付讲解：每轮「产物」横条

已完成 生成于 2026-08-18；基于真实 diff 与页面验收。改动前：想点开本轮 agent 写出的文件，得自己在若干工具调用里翻路径。现在：本轮结束就在消息末尾出现一排可点的文件名。

一句话结论

以前：每轮 agent 写完文件后，文件只藏在工具调用记录里，要手动找路径再看。现在：每轮回答结束时，本轮的 write/edit 写出的文件会自动聚成一条「产物 / Artifacts」横条，点文件名就借用已有的文件查看器打开。

生活类比

像外卖收据：结账后把这次点了哪些菜（写过哪些文件）列成一行，每个菜名都能点开看完整内容，而不是让你翻聊天记录猜。而且只列真正上桌（写盘成功）的菜，失败/被取消的下单不算。

人话链路

你发一条消息→ agent 用 write/edit 写文件→ 本轮结束→ 系统扫本轮工具调用、去重、跳过报错的写入→ 本轮最后一条回复下出现「产物」横条→ 点文件名→ 现有文件查看器打开该文件

动了哪几块

lib/artifacts.ts（新增）— 产物提取工具箱

纯函数 extractArtifacts：只看 write/edit；取 file_path ?? path；该次写入报错就跳过；文件名去重。没有任何副作用，最容易被测试。

tests/artifacts.test.ts（新增）— 9 条行为测试

覆盖收集 / 去重 / path 兜底 / 报错排除 / 非写盘工具忽略 / 边界。先见红再转绿，非「照着实现凑」。

components/ArtifactStrip.tsx（新增）— 横条 UI

一个很薄的展示件：没产物就什么都不渲染；有就排一列文件名按钮，点了把路径交出去。

components/ChatWindow.tsx（改动）— 把横条挂到每轮末尾

以「用户消息」为界把对话切成轮；每一轮的最后一条回复后面挂横条；本轮还在流式/运行中就先不显示，结束才出现。横条只渲染、不占 minimap 的缩略序号，不干扰上下跳转。

components/AppShell.tsx（改动）— 接通文件查看器

把已经存在的「打开文件」能力（原本给左侧文件树用）传给聊天区，横条点文件名直接复用，没另造新查看器。

怎么测（你也能验证）

1. 打开任意一个 agent 写过文件的会话（本机 :3030）。
2. 滚到对应那轮的最后一条回复 → 下方应出现「产物 / Artifacts」和几个文件名。
3. 点任意文件名 → 弹出已有的文件查看器并打开该文件。
4. 若某轮只读没写文件 → 那轮没有横条。

// lib/artifacts.ts —— 核心提取
export function extractArtifacts(turnMessages) {
  const failed = new Set(turnMessages
    .filter(m => m.role === "toolResult" && m.isError)
    .map(m => m.toolCallId));
  const seen = new Set(); const out = [];
  for (const m of turnMessages) {
    if (m.role !== "assistant") continue;
    for (const b of m.content || []) {
      if (b.type !== "toolCall" || !ARTIFACT_TOOL_NAMES.has(b.toolName)) continue;
      if (failed.has(b.toolCallId)) continue;
      const p = b.input.file_path ?? b.input.path;
      if (typeof p === "string" && !seen.has(p)) { seen.add(p); out.push(p); }
    }
  }
  return out;
}

没动什么 / 边界

  • 没改文件查看器本体（RightPanel / FileViewer / TabBar）——纯复用。
  • 没动后端/消息格式/…agent 会话管理、git、分支。
  • 只认 write 与 edit（pi 会话只会发这两个显式写盘工具）；bash 内部写文件无法可靠取路径，暂不覆盖。
  • 「报错写入跳过」是粗略排除——工具执行报错（isError）会排除；被取消/token 中断不保证每个都有报错标记。
