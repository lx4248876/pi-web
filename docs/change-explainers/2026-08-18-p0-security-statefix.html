pi-web 第一批修复 · 改动理解

Deep 档 · 2026-08-18 · 对应审计：P0 安全止血（CSRF 门禁 + 命令注入）+ 状态机正确性（S2/S3）
为什么这批最先修：当前 dev server 监听 0.0.0.0:3030（局域网可达）、全 API 零鉴权、git-status 等多处可被跨站请求直接触发命令注入——"任意网页 → 本机任意代码执行"的通道是真实存在的。本批修复先把这条总通道堵死，再修会话状态机的两个隐患。修复过程不改变任何 UI 观感，属于"看不见的安全加固"。

1. 一句话

给全部 /api/** 加服务端强制的前置校验（无 middleware 的仓库新建一个），把 git-status / open-terminal 的 shell 字符串拼接改成安全的数组参数，并修掉 useAgentSession 里"加载 effect 空依赖"和"自动重试跨会话污染"两个状态机隐患。

2. 改动地图（改哪里）

主改 1：新建 middleware.ts（仓库根目录 / 或 src/middleware.ts，取决于构建入口）

安全新建文件
  • 做什么：对 /api/:path* 统一校验 Host（仅允许 localhost / 127.0.0.1 / [::1] / 已配置的 allowedDevOrigins），并在写操作（POST/PUT/PATCH/DELETE）校验 Origin 白名单或 Sec-Fetch-Site ∈ {same-origin, none}。
  • 为什么：Host 校验挡住 DNS rebinding（攻击域名解析到 127.0.0.1 的跨源读取，含明文 API key）；Origin/Sec-Fetch-Site 校验挡住跨站 simple-request CSRF。这是堵"任意网页 → 本机 API"总通道的单一落点，零前端改动——前端 49 处 fetch 全部自动被保护。
  • 注意：不要用"允许所有 Origin + CORS 头"的方式（那会打开跨源读取）；只校验、不放行跨源。

主改 2：app/api/git-status/route.ts · 消灭 shell 拼接

安全修改现有文件
  • 现状（已逐行核实）：execSync(`git checkout ${branchName}`) 等 10 处把用户输入直接拼进 shell 命令串（L121/134/156/171/173/222/223/247/252/257/276/294/307），execSync 默认经 sh -c 执行，; / && / $() / ` 均可注入。
  • 改成：使用 execFile（或 spawn）数组参数：execFile("git", ["checkout", branchName], {cwd, encoding:"utf8"})。数组参数不经 shell，无注入面；行为（错误信息、exit code）保持兼容。
  • 顺带修：L316 的 write-file 分支二次 req.json()（body 已被 L9 消费，可能恒 500）→ 复用已解析 body；writePath 的 .. 穿越 → realpath containment（限定在 cwd 内，另限制 content ≤ ~5MB）。
  • 兼容性：所有 action（status/list-branches/checkout/merge/commit/rollback/push/pull/fetch/resolve-conflict/diff/commit-files/delete-branch/create-branch/write-file）返回的 JSON 结构不变，前端 GitPanel.tsx 无需改动。

主改 3：app/api/open-terminal/route.ts · pwsh 兜底分支去 shell

安全修改现有文件
  • 现状：Windows 兜底分支（L46-54）spawn("pwsh", ["-NoExit","-Command", `Set-Location -LiteralPath '${path}'`], {shell:true})——path 含 ' 即逃逸出单引号字面量，且 shell:true 在 Windows 走 cmd 可二次注入 &/|。
  • 改成：去掉 shell:true 和字符串命令，改用 spawn("pwsh", ["-NoExit","-WorkingDirectory", path], {detached:true, stdio:"ignore"})（pwsh 支持 -WorkingDirectory，原生数组参数）。macOS 的 open -a Terminal path 与 Linux 分支本来就是数组参数，保持不动。
  • 可选加严：对 path 加目录存在性 + isDirectory 校验（已有），或与 /api/files 白名单收敛（第二批评级做）。

主改 4：hooks/useAgentSession.ts · S2 加载 effect 空依赖

修改现有文件
  • 现状（L1294-1327）：effect 依赖 [] + eslint-disable，注释写"Load session when session changes"但实际只在挂载时跑一次；切换会话靠 AppShell.tsx:401 的 key={sessionKey} 整个重挂载兜底——隐性契约。
  • 改成：把 effect 改为依赖 [session?.id]（loadSession 本身引用稳定），先判断 if (!session) return;，让"切换会话即加载"行为自洽，不再依赖外部重挂载；删除误导注释，保留卸载清理（关 EventSource + 清 timer）。注意 connectEvents/loadTools 等引用进依赖或改用 ref，避免闭包过期。

主改 5：hooks/useAgentSession.ts · S3 自动重试跨会话污染

修改现有文件
  • 现状（L651-663）：message_end 检测到 provider 错误后 setTimeout(..., 1000) 发送"继续"；若用户在 1 秒窗口内切换了会话，这条重试会发到新会话。
  • 改成：setTimeout 前捕获 sessionIdRef.current，回调里先比对"仍是同一个会话"才发送；timer 句柄存入 ref，在会话切换/卸载时 clearTimeout。

可能波及（本批不主动动，但需验证不回归）

  • lib/agent-client.ts 及前端各 fetch 调用点：middleware 生效后所有 /api/** 请求都会过校验，需手动验证本机正常链路（localhost Origin/Host 天然通过）不误伤；跨 192.168.* 局域网访问（allowedDevOrigins 已配置）需要验证 Host 白名单覆盖。
  • app/api/sessions/[id]/events 与 app/api/agent/[id]/events（SSE）：EventSource 是 GET，无 Origin 携带自定义头（浏览器 EventSource 无法加头），middleware 需对 GET 只做 Host 校验（SSE 不该被 Origin 挡掉——但跨站 EventSource 会带 Origin，正好被 Sec-Fetch-Site: cross-site 拒绝，行为正确）。
  • Tauri/桌面壳访问（若经自定义 scheme 或 127.0.0.1）：Origin 可能为 null，middleware 需对 null Origin + 可信 Referer 的组合放行，否则桌面端可能被误拦——本批把放行条件写清楚，回归验证时重点测。

3. 逻辑链路（为什么这样串）

攻击路径 → 修复后的拦截点
当前漏洞路径修复落点
恶意网页 → fetch(http://localhost:3030/api/git-status, {method:POST, body:text/plain}) → req.json() 解析 → execSync("git " + 注入串) → RCEmiddleware 拒 Origin/Sec-Fetch-Site: cross-site → 第一步即断；即使放行，execFile 数组参数无 shell 可注
攻击域 DNS → 127.0.0.1（rebinding）→ 同源读 /api/models-config（明文 API key）middleware 校验 Host 白名单（攻击域不匹配）→ 断
恶意网页 → fetch(http://localhost:3030/api/open-terminal) → path 注入 pwshmiddleware 拦截 + -WorkingDirectory 数组参数无注入面
用户切会话 1 秒内 → 旧错误触发的"继续"发到新会话 → 上下文污染/误建新会话S3：捕获 sessionId + 回调比对 + timer 清理
切会话 → 新会话不加载（依赖 AppShell key 重挂载的隐性契约）S2：effect 补 [session?.id] 依赖，行为自洽
修复后应看到：本机正常使用零感知；打开浏览器 DevTools 无新增报错；更换会话后消息立即重新加载（不再依赖重挂载）；跨站模拟请求（可用 curl 带 Origin: https://evil.example）被 403。

4. 改完你应看到（验收观感）

  • npm run dev 后本机聊天 / Git 面板 / 文件浏览 / 终端 / 模型配置全部照常工作（回归无感知）。
  • curl -X POST http://localhost:3030/api/git-status -H "Origin: https://evil.example" -d '{"cwd":"C:\\","action":"status"}' → 返回 403（此前会执行）。
  • 用 curl 伪造 Host: evil.example 请求 /api/models-config → 403（此前返回含明文 key 的 JSON）。
  • Git 面板：含特殊字符（$()、;、中文、空格）的分支名/提交信息/路径不再被 shell 解析破坏，正常提交/切换/回滚。
  • tsc --noEmit 0 错误；npm test 全绿（utils 新测试 + 现有 62 个不回归）。
  • 快速切换两个会话（在 provider 错误自动重试的 1 秒窗口内切换），确认重试不会出现在新会话。

  • 不拆大组件、不动 UI、不加虚拟化、不换 PrismLight（后续批次）。
  • 不新增前端自定义请求头（middleware 服务端强制已足够，等发现浏览器端其他通道再补；EventSource 本就无法加头，服务端方案是唯一正确做法）。
  • 不调整 allowedDevOrigins / 不改变 3030 监听行为（那是部署决策，除非用户另行要求）。
