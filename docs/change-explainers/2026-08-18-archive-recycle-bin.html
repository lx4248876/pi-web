改动理解：把「归档会话」变成可找回的回收站，并显示会话名称与最后一句话

只读说明，确认后再改。目标：删除会话不再永久消失，而是移入归档列表可还原回原项目；同时归档列表每条显示会话名称 + 最后一句话。

⚠️ 涉及删除数据的语义变更（从「删文件」改为「软删除/回收站」），属于高风险区，评分按 Deep 档。改动会动到底层删除接口、会话列表、以及前端状态持久化。已经删除掉的文件无法恢复，本改动只管「之后」的删除。

一句话

给会话删除加一个「回收站」：DELETE 不再真正删文件，而是把该会话记入一个持久化的已删除集合；主列表过滤掉这些会话，归档弹窗把它们和「被关闭项目的会话」一起展示；归档里的「还原」能把它们放回原项目（同时补上会话的「最后一句话」展示）。

为什么改（现状与痛点）

现在归档弹窗只收录「被关闭/隐藏项目」下的会话，原因在 SessionSidebar.tsx 里 archived = allSessions.filter(s => hiddenCwds 包含 s.cwd)。 而主列表里点删除时，后端 app/api/sessions/[id]/route.ts 的 DELETE 直接 unlinkSync(filePath) 把 .jsonl 文件删掉，会话彻底没影。所以「我刚才删除的会话」永远不会出现在归档里——这就是你遇到的第一个 bug。 另外，归档行目前只显示 name || firstMessage + 时间 + 消息数，没有「最后一句话」，SessionInfo 里也没有 lastMessage 字段——这是第二个 bug。

改动地图（主改点，均已核实存在）

lib/types.ts· SessionInfo
加一个字段 lastMessage: string，承载会话最后一句话，供归档列表展示。字段是纯增量，不影响其它调用方。
lib/ui-state.ts· UiState / parseUiState / setUiState后端
给持久化状态加 trashedSessions: string[]（已删除会话 id 集合）。这是「回收站」的服务端落盘，机制照抄 hiddenCwds（写 temp 再原子替换，存在 pi agent 目录），避免 localhost / 127.0.0.1 源隔离把回收站记录弄丢。
app/api/ui-state/route.ts· PUT后端
PUT 现在只认 hiddenCwds 并整体覆盖；改为允许 { hiddenCwds?, trashedSessions? } 合并写入，读旧值→更新指定字段→写回，避免删另一字段的状态。
app/api/sessions/[id]/route.ts· DELETE后端
核心语义变更：不再 unlinkSync 删文件，也不再改写子会话 header 重挂父级（保留文件供恢复）；仍保留 getRpcSession(id)?.destroy() 停掉活动会话。删除入口照旧由前端调用，「记入回收站」的动作放到前端。删除后文件还在，主列表靠前端过滤。
lib/session-reader.ts· listAllSessions / 尾部读取后端
给每个会话补算 lastMessage：复用现有「读文件尾部」的 helper，从尾部最后一条 message 里取出文本（兼容字符串或 text 块、取用户或助手消息都行）。列表接口 GET /api/sessions 随之带出该字段。
components/SessionSidebar.tsx· trashedSessions / 过滤 / 归档弹窗 / 还原前端
（1) 新增 trashedSessions(Set) 状态，加载+合并+持久化整套照抄 hiddenCwds（服务端 /api/ui-state 为准 + localStorage 兜底 + 本地合并回写）。
(2) 主列表用一个「visibleSessions = allSessions 去掉 trashed 里的 id」的统一入口，让已删除会话不出现在主列表（子会话因其父被过滤会被树构建自动提升为根，天然成立）。
(3) 删除确认回调：仍调 DELETE，成功后把该 id 加入 trashedSessions 并持久化（而非消失）。
(4) 归档弹窗：收录范围 = 被关闭项目的会话 ∪ 回收站里的会话；每条新增一行「最后一句话」预览（用新 lastMessage）。
(5) 「还原」按钮分两种：回收站会话→restoreSession（从回收站移除，回到原项目）；被关闭项目会话→保持原 rememberCwd（还原项目）。

逻辑链路（删 → 归档 → 还原）

① 用户在主列表点删除 → 前端调 DELETE /api/sessions/:id（后端停活动会话、保留文件、不再删文件）→ 成功后把 id 写入 trashedSessions 并落盘（localStorage + PUT /api/ui-state）→ 触发列表刷新。
② 主列表渲染 → 统一入口过滤掉 trashedSessions 的 id → 该会话从主列表消失；其子会话因父会话被过滤而自动提升为根，不会悬空消失。
③ 刷新列表数据 → GET /api/sessions 现在带出 lastMessage，前端保留全量 allSessions（含已删除会话）。
④ 打开归档弹窗 → archived =（被关闭项目会话）∪（回收站会话），按 modified 倒序；每行显示 cwd + 会话名 + 时间·消息数 + 新增的最后一句话。
⑤ 点「还原」 → 回收站会话：把 id 从 trashedSessions 移除并落盘 → 立即回到主列表原项目下；被关闭项目会话：原 rememberCwd 还原整个项目。

改完你应看到

  • 从一个「仍可见/已关闭」的项目里删掉某个会话后，它从主列表消失，但打开「归档会话」弹窗能看到它（在最上面，因为刚动过）。
  • 归档弹窗每条会显示会话名 + 最后一句话（不只 name+时间+消息数）。
  • 在归档里点某条「还原」，该会话回到它的原项目下列出；反复删/还原不会丢记录，浏览器重启、换 localhost/127.0.0.1 打开都一致。
  • 「关闭项目」产生的归档会话行为不变（仍然只还原项目、不新增回收站语义）。

先别动（明确不做，避免范围失控）

  • 不做「空回收站 / 永久删除」按钮——文件会一直保留，本次不动它（后续可以做）。
  • 不改归档里「被关闭项目」会话的现有还原逻辑。
  • 不改变 session 文件本身的内容格式（trashedSessions 只作为外部 UI 状态并存，不写进 .jsonl）。
  • 不改主列表其它行的展示；lastMessage 只在归档弹窗新增展示。
  • 已删除（文件已没了）的历史会话无法恢复，不处理。

怎么测（你在浏览器里亲手验证）

  1. 打开 http://localhost:3030，左侧是一个项目下的会话列表。
  2. 在某个不重要的已完成会话上悬浮，点垃圾桶图标 → 确认 Delete。此刻该会话会从列表消失，但文件没删（在回收站里）。
  3. 点标题栏的「归档会话」按钮，弹出列表里应能看到刚删的会话，且每行多了一行最后的对话内容（最后一句话）。
  4. 点那一行的「还原」→ 弹窗关闭，该会话回到原项目的会话列表中。
  5. 反复删/还原几次，或刷新/换 localhost 与 127.0.0.1 打开，记录都还在（服务端持久化）。
