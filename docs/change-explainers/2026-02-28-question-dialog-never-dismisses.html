以前：弹窗会被新问题顶掉 / 会被会话中断悄悄取消 / 答错了还消失。

🧩 一句话结论

问题弹窗只在它所属的会话里显示，不跟着你切换会话。但任何会话只要还有未答问题，侧边栏就会给它标一个不打扰的「待答」徽标——刷新页面后两个会话的问题都在列表里一眼可见，点进即可作答，谁都不丢。

🔄 一个未答问题从发起到被答

  1. 1代理在该会话触发 question
    后端立刻发出带唯一编号的弹窗请求，并保持「未答」——不会再被会话中断悄悄取消（这是「问了却没弹窗」的根源，已修）。
  2. 2该会话的界面收到 → 弹窗
    弹窗只画在这个会话的窗口里；你切到别的会话它就不挡路，切回来它仍在（服务器一直记着，没丢）。
  3. 3后面的问题排队，不顶掉
    同一会话再发新问题，只是排到后面，不会把你正在答的顶掉。
  4. 4你答 → 送达服务器确认 → 收起
    答案先确保送到服务器、代理真收到才收起；送失败就留着让你重试。

③ 答了才算 · hooks/useAgentSession.ts
答案成功送达后才移出弹窗，失败保留可重试。
④ 【本次根因】重放以未答权威集合为准 · lib/rpc-manager.ts
旧实现只从脆弱的 eventBuffer 回放「未答问题」；若问题在有监听器时 live 投递（不进缓冲），刷新/切换时旧连接没干净摘掉、新监听器就已挂上，它就被错过——徽标在但点进去不弹。现在改用 pendingExtensionRequests（未答权威集合）直接回放，新监听器必然拿到所有未答问题。
没做 / 已回退：不做「任何会话的弹窗跟着你全世界跑」的全局面板。弹窗只属于它自己的会话，切换会话不会跟着你。

🧪 怎么自己验证（重启后）

① 不被顶掉：一个会话里让代理问 A，再触发第二次提问 → A 的弹窗还在，没消失；答完 A 才走。
② 切走不跟着：会话 1 问一个问题别点，切到会话 2 → 会话 1 的弹窗不挡你；切回会话 1 → 它还在，可答。
③ 答完才算：答一个弹窗 → 立即收起，且提问的代理继续走。
④ 不互卡：未答问题挂在那时，别的会话照常能跑能答（已有自动化测试锁定）。
