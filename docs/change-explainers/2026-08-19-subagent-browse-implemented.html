本次改动：web 页面能看到子代理（只读实时查看）

实现完成讲解页 · 2026-08-19 · 基于真实 diff · C:/A-codes/lix/pi-web

一句话结论

以前：你的主会话派生的子代理（subagent）跑在自己的会话文件里，藏在 `sessions/父会话/async-*/` 两三层的子目录中，web 侧栏完全看不到它。

现在：web 会把这些子会话递归捞进侧栏父会话下面（带运行/完成/失败状态点）；点开任意一个就能只读实时看它在想什么、调了什么（随跑随刷），且绝不会被当成可交互会话去启动/接管。

生活类比

想象主会话是「项目经理」，派出去干活的子代理是「外包小组」。以前外包小组在自己的工位（独立进程+独立文件夹）干活，会议室（web 页面）只摆着项目经理，你看不到小组在干啥。现在给会议室加了一块单向玻璃监控屏：可以实时看到外包小组接下来做的每一步，但你没法往玻璃里递纸条/下指令——他们仍是独立团队，你只是旁观。改动就是装这块「只读监控屏」：把小组的文件夹找出来、接上实时画面、并保证监控屏只有只读镜头、不给命令通道。

人话链路

你在 web 派子代理→ 子代理独立进程写自己 sessions/父/async-* 文件→ web 会话列表递归扫到它们→ 侧栏父会话下冒出子节点（转圈=运行中）→ 点击子会话→ 只读快照 + 只读尾读 SSE 实时刷新→ 子代跑完→绿/红点，跟随停止，输入框隐藏

动了哪几块

① 会话列表发现子会话 — lib/session-reader.ts

给会话列表补一个递归扫描，把两层深的子会话文件收进来，标记 browseOnly:true（只读）。顺带推导它的运行/完成/失败状态。

看代码区折叠
scanChildSessions(dir)      // 递归扫 sessions/父id/*/async-*/*.jsonl
isChildSessionPath(dir,file)// 某文件是不是子会话（供红线防护用，带 5s 缓存并与列表同步刷新）
readChildLiveStatus(file)   // 文件还在写+未终态 = 运行中转圈
listAllSessions()           // 末尾把子会话合并进列表（browseOnly:true）
② 只读实时尾读 — lib/subagent-live.ts + app/api/subagents/[id]/events（新增）

新增纯只读的 SSE 通道：反复读子会话文件、把「新增的消息」推给前端。它是唯一给子会话看的实时画面，与 pi 运行时彻底解耦（不依赖也不启动任何代理）。

看代码区折叠
class ChildSessionTailer { constructor: seenCount=已存在消息数 → 首 poll 不重放历史 }
sessionEntriesToMessages(file)  // 只提取 message 条目
GET /api/subagents/[id]/events  // tail 文件 → child_update / child_terminal
③ 红线防护：子会话绝不启动/接管 — lib/session-reader.ts + app/api/agent/[id]（POST）与 events

所有「能启动/接管代理」的共享入口，在真正启动前先判断目标是不是子会话：是则直接 403 拒绝。这样即使前端某个入口漏了，或有人直接 curl，也不可能为子会话拉起一个 agent 进程。

看代码区折叠
POST /api/agent/[id]  →  resolvePath → isChildSessionPath? → 403(禁止命令)
GET  /api/agent/[id]/events → isChildSessionPath? → 403(禁止交互通道)
（两处都放在 isAlive() 快路径之前，防泄漏 wrapper 也被兜住）
④ 前端：选中子会话走只读、隐藏输入 — hooks/useAgentSession.ts + components/ChatWindow.tsx

选中子会话时不再连普通交互事件通道，改连只读尾读 SSE；所有「发送/中止/分叉/导航/换模型/压缩」等命令处理都在只读子会话下直接忽略；ChatWindow 显示「👁 只读查看子代理」横幅、没有输入框。

看代码区折叠
connectChildEvents(sid)         // 尾读 SSE；child_terminal 时关闭连接防泄漏
handleSend/Abort/Fork/Steer/Navigate/LeafChange/ModelChange/Compact/... 均加 browseOnly 早退
ChatWindow: browseOnly → 只读横幅，不渲染 ChatInput
类型 — lib/types.ts

SessionInfo 增可选 browseOnly?: boolean，前端据此走只读分支。

怎么测（手动验收，不读代码）

准备：启动 web（npm run dev，端口 3030）。需要一个能派子代理的主会话（你的 pi 装了 pi-subagents）。

  1. 在 web 开一个主会话，让它调用 subagent 工具跑一个任务。
  2. 运行中子代理 1–2 秒内：侧栏主会话下冒出子节点，前面有个转圈。
  3. 点开那个子会话：主区显示「专只读查看子代理」横幅，没有输入框；子代理的思路/工具调用随跑随出现在面板里。
  4. 子代理完成后：转圈变绿（成功）或红（出错），实时跟随停止。
  5. 安全兜底（可选）：对这个子会话 id 直接 curl -X POST /api/agent/<childId>，应返回 403，证明它永不被当作可交互会话。

没动什么 / 风险边界

  • 没动 pi 运行时 / pi-subagents：子代理仍由 pi 自己的独立进程跑，本改动只在 web 侧「只读旁观」。
  • 不做全局子代理列表、不做发起 subagent、不做工作区隔离（本次范围=当前父会话的子会话可见+只读查看）。
  • 不改普通可交互会话的事件通道（/api/agent/[id] 与既有行为保持）。
