🧭 待答徽标：从「只数打开中的」改为「文件里有就算」

一句话结论：以前侧栏「待答」徽标只数当前进程里正打开的会话；现在它还会去翻会话文件，只要某个会话的文件里挂着一条还没回答的问题，就算进去——即使你关掉它 / 进程重启 / 闲了很久，徽标也亮。
🍵 生活类比：把每个会话当成一张「待办纸」。旧办法是——只有你（进程）此刻正拿在手里那几张纸，徽标才数得到；纸被放下、或者你人走开 10 分钟把纸收进抽屉（idle 销毁），徽标就把它「忘了」。新办法是——每次点一下徽标，都会去翻一遍所有文件抽屉，凡是有张纸最后一行写着「这有个问题等你回」，就给你点亮。纸在哪不重要，只要问题还写在上面就露出来。

📌 你做了什么 → 系统从哪进 → 你看到什么

侧栏徽标每 4 秒轮询一次后端接口 /api/pending-questions。这次改动让那个接口在「内存里正在打开的会话」之外，再并上「从会话文件里读出有未答问题、但本进程没打开的会话」，然后按会话 id 去重返回。你看到的结果就是徽标残留不再莫名其妙消失。

// lib/rpc-manager.ts —— 新的合并函数（部分）
function unionPendingDialogs(memory, file) {
  const seen = new Set(); const out = [];
  for (const d of memory) { if (seen.has(d.sessionId)) continue; seen.add(d.sessionId); out.push(d); }
  for (const d of file)   { if (seen.has(d.sessionId)) continue; seen.add(d.sessionId); out.push(d); }
  return out;
}
// 文件侧扫描：枚举顶层会话 → 跳过已覆盖的 → 解析叶子未答问题 → 并入
async function scanFilePending({ excludeIds }) {
  const out = [];
  let sessions; try { sessions = await SessionManager.listAll(); } catch { return out; }
  for (const s of sessions) {
    if (excludeIds.has(s.id)) continue;
    const recovered = readCachedUnansweredQuestion(s.path);   // 按 文件大小+修改时间 缓存
    if (!recovered) continue;
    out.push({ sessionId: s.id, request: { type: "extension_ui_request", ...recovered.request } });
  }
  return out;
}
export async function getAllPendingDialogs(scanner = scanFilePending) {
  const memory = collectMemoryPending();
  const file = await scanner({ excludeIds: new Set(memory.map(d => d.sessionId)) });
  return unionPendingDialogs(memory, file);
}

😌 没动什么 / 边界

  • 没动 前端组件、subagent 面板、pi 运行时、会话文件的写入格式——纯后端聚合补强。
  • 没动 已确认保留的已知边界：扩展工具直接调 ctx.ui 弹的窗（非 question 工具）仍需开发侧写 side-channel 才能恢复，本次按决策留档不修。
  • 已知边界 只扫顶层会话，子会话（subagent，本就浏览-only）不挂未答徽标，与旧行为一致、非回归。
  • 已知边界 瞬时读文件失败会漏一拍徽标，但下轮轮询自动自愈。
