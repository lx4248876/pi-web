📌 两个新能力：弹窗大小会「记住」了 + 模型可以配「自动瘦身」了

本次改动 2026-08-20 · pi-web（本地 Web 控制台）

❌ 以前Models / Skills / 插件市场三个设置弹窗大小写死（860×78vh 等），既不能拖大拖小，刷新后也不会记住你上次调的大小。自动压缩只有一套全局默认（16384 tokens 预留），面板上没有任何开关。
✅ 现在三个弹窗都能拖标题栏移动、拖右下角手柄调大小，刷新页面后原样恢复。每个模型可以单独填一个「自动压缩阈值」——上下文涨到这个数就自动压缩历史；压缩期间输入框锁定防误发；留空就完全不启用自动压缩。

🏠 生活类比

弹窗尺寸记忆就像你家窗帘：以前每次拉开都回到厂家固定的位置；现在你拉到哪，窗帘轨道就「记住」哪，下次还是停在那个高度。

自动压缩阈值就像笔记本的「换页规则」：一本笔记本（模型的上下文窗口）写满了就得把前几页撕下来抄成摘要（压缩历史）。以前是不管你写多满、系统固定在「剩 1.6 万字就换页」；现在你可以在每个本子封面上写「写到 8 万字就换页」，也可以写「永远别自动换页」（留空）。换页的那几秒钟，笔会被暂时收走（禁止发送消息），抄完摘要再还给你。

⚙️ 功能二：模型级自动压缩阈值（怎么串起来的）

你在模型面板填一个数字

Models → 选某个模型 → 「自动压缩阈值 (tokens)」填如 800000，保存。这个数字存在 models.json 里那个模型的条目上（每个模型各配各的）。

会话启动 / 切模型 / 改配置时自动换算

后台把「阈值」换算成 pi 引擎认识的参数：预留量 = 窗口大小 − 阈值（例：100 万窗口、80 万阈值 → 预留 20 万）。这个换算只存在会话内存里，不污染全局配置文件。

上下文涨到阈值 → 自动压缩

每轮对话结束后引擎检查：上下文 tokens 超过阈值，就把旧历史抄写成摘要，腾出空间。压缩期间输入框变成「正在压缩上下文，请稍候…」，发送按钮锁死；后台也有一道保险，压缩中发来的消息会被直接拒绝。压完自动解锁。

没填 = 完全不启用

留空的模型，自动压缩被显式关闭（包括「快撑爆了才压」的兜底）——溢出时会直接报错，这是你选择「不自动压」的字面后果。

看功能二动了哪几块代码
  • 换算核心（纯函数）：阈值→开关+预留量、压缩中拦截判断lib/compaction-override.ts
  • 会话管家：启动/切模型/重载配置三处应用换算；压缩中拦截发送/打断/排队三种消息lib/rpc-manager.ts
  • 模型面板：新增「自动压缩阈值」输入框 + 说明文字components/ModelsConfig.tsx
  • 聊天输入框：压缩中锁发送（按钮/回车/排队/占位提示）components/ChatInput.tsx
⚠️ 两个要知道的边界：① 阈值必须小于该模型的 Context window（填了更大的数 = 无效，等于没开）；② 留空关闭自动压缩是「彻底关」——连上下文溢出时的兜底压缩都没有了，溢出会直接报错让你手动 Compact。
