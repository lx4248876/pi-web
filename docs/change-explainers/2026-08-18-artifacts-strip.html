改动理解：每轮「产物」横条

Standard 生成于 2026-08-18；基于仓库当前只读核实。

一句话

每一轮 agent 回答完成时，自动采集该轮里 agent 用 write / edit / multiedit 等工具实际写入或修改过的文件（去重），在这轮助手消息末尾渲染一条「产物」横条； 点文件名直接复用已有文件查看器（RightPanel → FileViewer）打开查看。

改动地图

主改components/ChatWindow.tsx · 消息渲染 + 本轮产物采集

给每轮助手消息末尾加产物横条的渲染点，并从该轮消息里提取产物文件路径。

怎么改 / 为什么

在这轮最后一条助手消息渲染完成后，追加一条「产物」横条。采集逻辑顺着该轮 （从上一轮用户消息之后到这轮 assistant 消息）扫 toolCall 块：只在 toolName 命中写盘工具（write/edit/multiedit 等）时， 从 input 里读 path / file_path，按路径去重。 用该调用的 toolResult.isError 粗略排除「报错、可能没写成功」的调用，降低误列。 横条上的每个文件名点击后调用一个新的 onOpenFile(filePath, fileName)。

为什么落在这：文件列表完全来自前端已有的 messages（工具调用本就带路径），无需后端加数据； 而整个聊天气泡、滚动、结束时机都由 ChatWindow 统一负责，产物横条作为本轮消息的收尾自然归属这里。

主改components/AppShell.tsx · handleOpenFile 下传

把已经存在的打开文件能力接通到 ChatWindow。

怎么改 / 为什么

AppShell 里已有 handleOpenFile(filePath, fileName)（开标签页 + 弹文件查看器）。 给它加一条 prop，通过 <ChatWindow onOpenFile={handleOpenFile} /> 传给聊天区， 产品横条点文件名时就能直接复用现有文件查看器，不用新建一套打开逻辑。

波及新增小组件承载横条 UI（例如 components/ArtifactStrip.tsx）

把「产物」横条的展示样式单独成件；也可内联在 ChatWindow，属于实现取舍。

怎么改 / 为什么

一个很薄的展示组件：接收一份去重后的文件路径数组，渲染成一行小芯片/文件名按钮，点击调 onOpenFile。单独成组件便于复用与测试；不包含任何后端或持久化逻辑。

波及滚动/自动贴底逻辑

横条会改变本轮消息的高度，需接入既有自动滚动判定。

怎么改 / 为什么

ChatWindow 已按 messages.length / streamState / loading 重新评估滚动与「滚动到底部」按钮， 新增横条后把「产物是否变化」并入依赖即可，避免用户在看底部时横条动态插入导致跳动。

逻辑链路

用户发消息→ 本轮开始 agent_start→ agent 跑写盘工具 write/edit/multiedit→ 本轮结束 agent_end→ ChatWindow 按本轮 toolCall 提取文件路径并去重→ 本轮末尾渲染「产物」横条→ 点文件名→ AppShell.handleOpenFile→ RightPanel → FileViewer 打开该文件

改完你应看到

  • 每轮 agent 回答完成后，末尾出现「产物」横条，列出该轮写入/修改过的文件名（已去重）。
  • 点某个文件名，弹出已有的文件查看器（多标签弹窗）并打开该文件，可查看 / 编辑 / diff。
  • 纯问答、本轮没写文件的一轮，不显示横条。
  • 本轮还在 stream / 运行中（agentRunning）时不显示横条，等本轮真正结束才出现，避免列半成品。

先别动

  • 不改文件查看器本身（RightPanel / FileViewer / TabBar 已够用，直接复用）。
  • 不动后端：不碰 rpc-manager、消息持久化格式、git 状态解析、分支。
  • 不做「会话级聚合产物页」——已按你的选择定位到每轮横条。
  • lib/types.ts 尽量不动；路径提取可用 MessageView 里已有的 getToolPreview 同款思路局部实现。

未知与假设

  • 未知：「写盘工具」的精确名单——假定 write / edit / multiedit 及同类显式带 file_path 的工具；无法从 input 直接取路径的工具（如 bash 内部写文件、 apply_patch 等）先不覆盖。
  • 未知：代码里没有现成的「文件确实已写盘」标志，只能用该调用的 toolResult.isError 粗略排除失败的写入，不是 100% 保证。
  • 假设：读取现有 messages（来自 .jsonl 历史 + 实时流）即可，不需要后端新增数据； 实时流下本轮 toolCall 块在本轮结束时已齐全。
  • 材料：够——ChatWindow / AppShell / RightPanel / FileViewer / lib/types.ts / MessageView 均已核实存在。
