改动理解：恢复并补全提示音（任务完成 + 需要提问）

Standard 生成于 2026-08-18；基于仓库只读核实。

一句话

把“任务完成后提示音”从当前坏实现（靠临时改 handleAgentEventRef，会被 useAgentSession 每次渲染冲掉）换成可靠接线（直接包 onAgentEnd 回调），修复 useAudio 的 AudioContext 自动播放策略问题；再补上“需要提问（弹窗请求）”时的独立提示音。

改动地图

components/ChatWindow.tsx · onAgentEnd 传入处 / 声音监听 — 白话职责：任务结束、提问弹窗出现时触发发声
怎么改 / 为什么

任务完成音：删除现在用 useEffect 改写 handleAgentEventRef.current 的那段（ChatWindow.tsx:645-654）。改在 useAgentSession({ ... }) 调用处，先包一层 onAgentEnd：包里的回调先判断声音开关、播放完成音，再调用原来的 onAgentEnd。因为 useAgentSession 在 agent_end 时是统一调用这个回调（useAgentSession.ts:608），且不依赖那个会被每次渲染覆盖的 ref，所以声音一定能触发。

提问音：新增一个 useEffect 监听 pendingUiRequest，当它从空变成非空（也就是 agent 抛出一个 question/confirm/input/multiple 弹窗）时，播放一个和完成音不同的提示音。这样不需要改动 useAgentSession 的业务逻辑。

hooks/useAudio.ts · playDone / 新增 playAsk — 白话职责：声音开关 + 实际播放
怎么改 / 为什么

复用同一个 AudioContext 实例，每次播放前若处于 suspended（浏览器自动播放策略常见的状态）就 resume()，不再每次 new AudioContext() 后立刻 close()。否则在无障碍点击的刷新/后台场景里，新上下文被挂起，发不出声音——这是“任务完成音”个因性失效的第二个源头。

新增一个 playAsk 提示音（音色/音高与完成音区分，例如三连短音），同样遵守声音开关并复用同一 AudioContext，暴露给 ChatWindow 使用。

components/ChatWindow.tsx · useAudio() 解构处 — 白话责任：把新加的 playAsk 解构出来并接进 pendingUiRequest 监听；handleAgentEventRef 的包装代码删除后该 ref 不再被外部改写。

逻辑链路

用户发起/继续任务 → SSE: agent_end → useAgentSession 调 onAgentEnd() → 包好的回调：playDoneSound()（若开启） → 用户听到完成音
agent 调用问题/确认工具 → SSE: extension_ui_request → useAgentSession 设置 pendingUiRequest → ChatWindow useEffect 检测变非空 → playAsk() → 弹出对话框 + 用户听到提问音

改完你应看到

  • 任务跑完（不手动中止）时，只要声音开关开着，就一定能听到完成提示音；切后台切回来也应正常响。
  • agent 需要向你提问/要确认（弹出 question / confirm / input / multiple 弹窗）时，会听到一个与完成音不同的提示音。
  • 输入区右上角的声音开关仍正常工作，关闭后两者都不响。

先别动

  • 不改 useAgentSession 的事件分发逻辑（不新增事件类型、不改 handleAgentEventRef 内部结构），问题只在调用侧接线。
  • 不做浏览器原生 Notification 系统通知、不做 TTS 语音朗读任务内容——本期只要提示音。
  • 音频节奏/音量不变，保持安静低调，不改主题皮肤相关样式。

未知与假设

  • 未知：不同浏览器自动播放策略对“首次 AudioContext 由非用户手势创建”处理有差异；复用单实例已在历史修复（2cb929e）中被验证可行，但当前 main 未含该改动。
  • 假设：pendingUiRequest 在弹窗出现时才从 null 变非 null（已在 ChatWindow:543 解构、useAgentSession 里由 setPendingUiRequest 设置，Grounding 已核实）。其只在弹窗消失后回 null，不会在 agent 提问期间重复触发。
  • 未知：提问音与“多连问（multiple）”是否要逐问响一次——暂定每次弹窗出现响一次。
