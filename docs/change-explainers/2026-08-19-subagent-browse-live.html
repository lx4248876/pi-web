改动理解：子代理可见 + 只读实时尾读

Deep 生成于 2026-08-19；基于仓库只读核实（C:/A-codes/lix/pi-web）。

⚠ 高风险：本改动涉及「会话」读取/状态判定。风险主要是「误把只读浏览当成可交互会话去启动 agent」。本设计用「子会话=只读尾读、绝不 startRpcSession」的硬边界隔离它，且不动 pi 运行时。详见「未知与假设」置顶段。

一句话

让 web 页面能看到子代理：递归把藏在 sessions/<父id>/… 里的子会话捞进侧栏父节点下（带运行/完成/失败状态点），点击后以只读方式浏览该子代理；对仍在跑的子代理做文件尾读实时跟踪，随它边跑边刷。全程不启动、不接管子代理进程。

改动地图

lib/session-reader.ts · listAllSessions — 会话列表入口（主改）
怎么改 / 为什么

现状只调 SessionManager.listAll()，而 pi 的 listAll 只扫 sessions/<目录>/*.jsonl 一层子目录，子代理文件在两级深处，所以根本看不到。改成：在原列表基础上额外递归遍历 sessions/<父id>/async-*、chain-*、dynamic-* 等子目录里的 .jsonl，合并成同一个 SessionInfo[]（带 parentSessionId 归组）。为结果加一个「这是子代理会话」的 browseOnly 标记，并复用现有 tail 缓存为它推导状态。

app/api/subagents/[id]/events/route.ts（新建）— 子会话只读尾读 SSE（主改）
怎么改 / 为什么

新增一条只读的 SSE：tail 目标子会话的 .jsonl，把新增条目实时推给前端。硬边界：这条路绝不调用 startRpcSession / getRpcSession，也不依赖活跃 RPC 会话。以此避免复用现有 /api/agent/[id]/events（那条会尝试启动活跃 agent，对浏览式子会话禁止）。用 mtime/size + offset 增量读，控制开销。

hooks/useAgentSession.ts · loadSession / connectEvents — 前端打开分支（主改）
怎么改 / 为什么

当前选中普通会话时若 agentState.running 会连 /api/agent/[id]/events（可交互通道）。给选中项加一个 browseOnly 分支：子代理会话走 /api/sessions/[id] 只读快照 + 打开上面的子代理尾读 SSE，且不发任何命令。这样必然只读，天然符合仓库「浏览会话必须只读、不 spawn 活跃 agent」的铁律。

components/ChatWindow.tsx + components/SessionSidebar.tsx — 只读观感 + 子节点状态点（主改）
怎么改 / 为什么

选中子会话时隐藏 ChatInput（只读观看，不可发送）；侧栏已按 parentSessionId 把子会话归到父节点下（树结构现成），补上对运行中子代理的「转圈」状态点（由文件仍在跑判定）。这样用户能直观看到「父在跑 → 底下冒子节点 → 转圈 → 停 → 绿/红」。

lib/types.ts · SessionInfo — 增加 browseOnly 标记（波及）
怎么改 / 为什么

给 SessionInfo 加一个可选 browseOnly（或 isChild）。前端据此走只读分支、隐藏输入框、限制改名/删除按钮。

lib/rpc-manager.ts — 侧限：不改注册表，也不加子代理 RPC（波及）
怎么改 / 为什么

不改 globalThis.__piSessions、__piStartLocks、getActiveRpcSessionIds。运行中子代理的状态不靠注册表，而从文件 mtime 仍增长 + tail 未收尾推导。保持「pi-web 只管顶层会话」的边界，降低对既有稳定的影响。

app/api/sessions/route.ts / [id]/route.ts — 预期复用、需回归确认（波及）
怎么改 / 为什么

/api/sessions 直接复用 listAllSessions 输出，无需改；/api/sessions/[id] 已能只读打开子会话（getRpcSession(child)=undefined → running:false，前端不会误连交互通道）。但要回归：PATCH 改名 / DELETE 软删除落到子会话的语义需确认，前端对子会话隐藏这两个入口以免误操作。

逻辑链路

父会话开跑agent 调 subagent子进程写 sessions/<父id>/async-*→ listAllSessions 递归发现侧栏父节点下冒子节点(转圈)→ 点击子会话useAgentSession 识别 browseOnly→ /api/sessions/[id] 只读快照打开子代理尾读 SSE→ 输入框隐藏子代理边跑边刷→ 文件停增→绿/红、跟随停止

改完你应看到

  • 父会话跑子代理后，侧栏父节点下实时冒出子会话节点，带「转圈」运行点。
  • 点击任一子会话，主区以只读方式实时显示该子代理的进展（消息/工具随跑随出）。
  • 子代理停下后状态点转绿（完成）或红（出错）；实时跟随自动停止。
  • 浏览子会话时输入框隐藏，不会误触发「继续/发送」去接管子代理。
  • 既有顶层会话的创建/交互/列表完全不变。

先别动

  • 不动 pi 运行时 / pi-subagents 扩展（子代理照旧由 pi 自己进程跑）。
  • 不启动、不接管、不可对子会话发交互命令（专注只读观看）。
  • 不做「全局子代理列表」「Subagent 发起」「工作区隔离」（本次收敛到“当前父会话的子会话可见 + 只读查看”）。
  • 不改现有 /api/agent/[id]/events 会话交互通道（它用于可交互会话，保持原样）。

未知与假设

风险置顶：本功能触碰「会话读取 + 状态判定」。若把子会话误当成可交互 RPC 会话，会产生凭空启动 agent 的副作用。落地时以「只读尾读、绝不 start」为硬边界，并以最小回归验证（打开 /api/sessions 列表、打开一个子会话、确认无新生 RPC 进程）守住。

  • 未知：pi-subagents 是否在某些场景把子会话写到 os.tmpdir()（getSubagentSessionRoot 仅当「无父 session 文件」才走 temp；pi-web 里父都是 pi-web 建的，故应有父文件，但需真机确认）。
  • 未知：子代理结束后，sessions/<父id>/async-* 历史文件是否保留（取决于 pi-subagents 清理策略）；若被删，历史子会话可能不显示——需联调观察。
  • 未知：子代理「运行中」无官方事件，只能靠「mtime/size 仍增长 + tail 未收尾」判转圈；阈值需联调微调。
  • 假设：子代理由独立 pi 进程以 --session-dir 写法落到 sessions/<父id>/ 下，可被跨进程递归扫到；此路径稳定。
  • 材料：够 — 已核实子会话落位（pi-subagents getSubagentSessionRoot + --session-dir）、pi listAll 单层扫描局限（session-manager.js）、只读打开路径（/api/sessions/[id]）、前端通道（useAgentSession connectEvents）。
