🔧 未答问题弹窗不再因进程重启而消失

改的是会话查看器（pi-web）里「提问弹窗」的恢复机制 — 2026-08-21

💡 一句话结论：以前，一个会话在「问了一个问题、还没等你回答」时若被关闭或重启，那个问题弹窗就永久不见了，即使你再次打开这个会话也看不到它、答不了它。
现在：再次打开这个会话时，系统会自动把那个没答的问题重新弹出来，你回答后答案会真实写回历史里，不会丢失。

🧩 用生活类比理解

想象一个餐厅点单小票（会话文件）。服务员口头问「先生请问加辣吗？」（把问题记在小票上），然后有一个「待应答」的小铃铛（弹窗）一直挂在墙上提醒。
问题在哪：这个小铃铛是插在电源插座上的电子牌（内存）——一旦餐厅停电/重启（进程重启），电子牌就灭了；小票上明明还写着「加辣吗」，可是没人再照着它把问题重新挂起来，于是这个没答的问题就被彻底忘了。
修复：重启后，店员会重新看小票（会话文件），发现上面还有个没答的「加辣吗」，就手动把铃铛重新挂上。你回答了，店员把它记回小票（写入历史），以后就不会再重复问。

🔍 人话链路：一次完整发生了什么

① 会话提问
助手要向用户提问时，会写一条question工具调用记进会话文件，并同时弹一个待答弹窗。弹窗本身是内存状态，只活在当前运行中的程序里。
② 进程重启 / 关闭（旧 bug 触发点）
如果程序在这个问题还没被回答时就退出了，内存里的弹窗随之消失。会话文件里那条「没答的问题」还在，但没有任何机制去读它再弹出来 —— 问题看起来被永久吞掉了。
③ 重新打开会话（新行为）
现在重新打开这个会话时，系统扫描会话文件当前结尾：若最后一条是「还没有对应回答的提问」，就把它重新恢复成一个弹窗（有选项→选择框；纯文字→输入框）。
④ 你回答问题后
你的答案会被当作一条普通用户消息写回会话历史（持久化，不再丢）。因为答案成了新的「最后一条」，下次再打开时系统看到结尾已是回答而不是问题，不会重复弹同一个问题。

▶ 新增：读出未答问题 session-reader.ts 
export function resolveLeafUnansweredQuestion(entries: SessionEntry[]): RehydratedQuestion | null {
  const resolved = new Set<string>();
  let lastMessage: SessionEntry | undefined;
  for (const e of entries) {
    if (e.type !== "message") continue;
    const msg = (e as SessionMessageEntry).message;
    if (msg.role === "toolResult" && (msg as ToolResultMessage).toolCallId) {
      resolved.add((msg as ToolResultMessage).toolCallId);
    }
    lastMessage = e;
  }
  if (!lastMessage) return null;
  const lm = (lastMessage as SessionMessageEntry).message;
  if (lm.role !== "assistant") return null;
  const content = Array.isArray(lm.content) ? lm.content : [];
  for (const rawBlock of content) {
    const block = rawBlock as unknown as Record<string, unknown> | null;
    if (!block || block.type !== "toolCall") continue;
    const toolName = blockField(block, ["toolName", "name"]);
    const toolCallId = blockField(block, ["toolCallId", "id"]);
    if (toolName !== "question" || typeof toolCallId !== "string") continue;
    if (resolved.has(toolCallId)) continue;
    const rawArgs = blockField(block, ["input", "arguments"]);
    const params = rawArgs && typeof rawArgs === "object" && !Array.isArray(rawArgs) ? rawArgs : {};
    const parts = resolveQuestionParts(params);
    if (parts.length !== 1) continue;
    const part = parts[0];
    const method = part.options.length > 0 ? "select" : "input";
    return { toolCallId, request: { method, title: part.title, question: part.question,
      placeholder: part.placeholder, ...(method === "select" ? { options: part.options } : {}) } };
  }
  return null;
}
▶ 打开会话时恢复弹窗 + 作答落盘 rpc-manager.ts 
// 在 startRpcSession 里，wrapper.start() 之后：
try {
  const sm = wrapper.inner.sessionManager;
  const entries = sm.getEntries?.();
  if (entries) {
    const recovered = resolveLeafUnansweredQuestion(entries);
    if (recovered) wrapper.rehydrateUnansweredQuestion(recovered);
  }
} catch (err) {
  console.error("[rpc-manager] recover pending question failed:", err);
}

// 新方法：注入等待弹窗 + 回答时写一条 user 消息落盘
rehydrateUnansweredQuestion(recovered) {
  const id = `rehydrate:${recovered.toolCallId}`;
  const requestEvent = { type: "extension_ui_request", id,
    method: recovered.request.method, title: recovered.request.title,
    question: recovered.request.question, placeholder: recovered.request.placeholder,
    ...(recovered.request.options ? { options: recovered.request.options } : {}) };
  this.pendingExtensionRequests.set(id, {
    requestEvent,
    resolve: (response) => {
      this.pendingExtensionRequests.delete(id);
      const answer = response && "value" in response ? response.value : undefined;
      if (answer === undefined || answer === null) return; // 取消/空答：不落盘，下次仍恢复
      try {
        sessionManager.appendMessage({ role: "user",
          content: [{ type: "text", text: String(answer) }] }); // 答案写入会话历史
      } catch (err) { console.error("[rpc-manager] append recovered answer failed:", err); }
    },
    reject: () => this.pendingExtensionRequests.delete(id),
  });
}

🚧 没动什么 / 已知边界

  • 不自动继续：恢复弹窗只是把问题重新摆出来让你回答，不会擅自让 AI 接着跑；答完后由你正常发下一条开始。
  • 不伪造结果：不往会话里硬塞一个虚假的「工具结果」，避免污染历史；答案以「用户消息」形式落盘。
  • 只恢复当前结尾的悬空问题：更早历史里的旧问题不会被反复考古重弹。
  • 一条消息里同时问多个问题：会整体恢复成一次「多问弹窗」，逐问作答后一并写回历史。
  • 恢复失败不会影响会话打开，仅损失一次恢复机会（有日志）。
