pi-web Bug 修复讲解

本次修复 8 处，排除 4 处疑似问题（经核实不是 bug）。以下是每处的来龙去脉，给不会写代码的你也能看懂。
一句话结论：修好了一些"可能在特定情况下出错/卡住"的隐患，让程序更稳、测试能真正跑起来；另外有 4 处查证后是"本就这样"，没动它们。

生活类比

想象一套"外卖调度台"（pi-web 是 pi 编码助手的前台，负责把大脑和对外的界面连起来）—— 有时它会在"没人接线时错过一通电话"、"拨号时占线不挂断"、"两单同时来却用了同一张单号"、 "帮你自动回拨却静静没打"。本次就是把这几根线理清楚，让该响的响、该挂的挂、该打的打。 另有几处检查后发现是"原本设计就如此"，就没乱动。

人话链路总览

你在界面操作（选模型、发消息、删文件勾选、新建对话）
请求进到后台调度台（lib/ 下的会话管家、钩子）
它把话转给 pi 助手大脑，再把大脑的动静推回界面
你现在看到的核心修复，都在"转话/推回/排队/下单"这几环

修复了哪些（8 处）

已修 B1测试终于能跑了

原来的测试里有一个跑不起来（缺一个能翻译代码的翻译器），等于那块"防弹窗丢失"的保护逻辑从没被验过。现在给它配上翻译器，并加了统一的 npm test 一键跑全量。是你拍板停掉的一个旧预览服务器占着文件导致装依赖失败，恢复后已正常。

看改动代码
# package.json
"test": "node --test \"tests/**/*.test.mjs\" && node --import jiti/register --test \"tests/**/*.test.ts\""
# 并把 jiti 登记为开发依赖
已修 B2切模型时不再"卡死等网络"

给大脑换模型时，如果当前列表里一时找不到那个模型，它原来会去联网刷新列表且不设超时——网络一慢就被挂住。现在改为只用本机缓存找，找不到就如实提示，不再干等。

看改动代码
// lib/rpc-manager.ts
await runtime.refresh({ allowNetwork: false }); // 之前是 await runtime.refresh()（联网、无超时）
已修 B3"自动重试"看清最新状态

大脑报错后界面想自动补一句"继续"。原来它握的是很久以前的快照，可能把话发错地方。现在改成实时拿最新状态再发。

已修 B4"自动继续"真正发得出去

发那句"继续"时，界面仍以为大脑还在忙，于是一句"你忙，我先不打扰"把它拦下——结果是静默不重试。现在明确放行这次的自动重试。

看改动代码
// hooks/useAgentSession.ts
handleSendRef.current?.("继续", undefined, { bypassRunning: true });
// handleSend 签名加 opts，守卫改为：if (agentRunning && !opts?.bypassRunning) return;
已修 B6启动失败时不"漏个孤儿"

建对话时若挂扩展组件失败，原来会留下一个没登记、没关闭的残留会话（占着日志文件）。现在失败就主动关闭清理，再报错。

已修 B7新会话单号不再撞车

几乎同时开两个新会话时，原来可能撞上同一个毫秒时间戳，两人拿到同一张"单"（用错目录）。现在每单用唯一随机号。

已修 B11顺手删一行没用的代码

Git 面板里有一个算了但没用的变量，纯属冗余，删掉。

查证后"不是 bug、没动"（4 处）

排除 B5 小挂件逻辑：官方契约里它本来就只收"数组或空"，不是漏了字符串。
排除 B8 界面其实根本没读那个"写死 0"的字段，不影响任何显示。
排除 B9 编辑器让用户长时间写内容时不该被超时打断，属于设计。
排除 B10 一个纯重复计算的性能小点，结果一样，不改。
